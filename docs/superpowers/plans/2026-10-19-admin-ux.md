# Admin UX Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the portfolio admin fast to edit and hard to get wrong, starting with a Skills × Evidence matrix and a content-health dashboard (batch 1), then speed, safety, preview and media batches.

**Architecture:** Pure, unit-tested logic in `src/lib/admin/*` (health checks, matrix model, link diffing) feeds server components that load the admin's full content once, and small client islands for interaction. All writes stay in `src/app/admin/actions.ts` behind `requireAdmin()` + RLS, followed by `updateTag('content')`.

**Tech Stack:** Next.js 16 (Cache Components), React 19, Supabase JS, Tailwind v4, shadcn/radix (`src/components/ui`), `motion/react`, `@dnd-kit`, `cmdk`, `sonner`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-admin-ux-design.md`

## Global Constraints

- Zero cost; Supabase Free limits (500 MB DB, 1 GB storage); no new paid services; new dependencies small and justified.
- Every write: server action → `requireAdmin()` → Supabase write (RLS still applies) → `updateTag('content')`.
- Anything reading the session or `params` sits inside `<Suspense>` (Cache Components).
- `contentSchema` fields do not change. DB changes are new, additive migrations only (preview shares the production DB).
- UI copy in Vietnamese; admin only, `noindex`.
- One PR per batch; CI green; owner tests the preview with the checklist in the PR body before merge; at most one polish fix round.
- Commits have no attribution lines.

## Review Focus

1. A skill linked only to hidden experiences/projects looks "linked" in the admin but has no evidence on the public site → `link-to-hidden` health issue and a distinct matrix cell style (Task 1, Task 3).
2. Rapid clicks on the same matrix cell (on → off → on) must end in the last state, with no duplicate-row error from the unique constraint → Task 2 test "toggling twice is idempotent" + Task 3 per-cell request ordering.
3. Saving a project's "Skills used here" must not touch links that belong to other projects/experiences of the same skill → Task 2 diff test.
4. Health checks on empty or partial content (no why cards, a role with an empty `experienceOrder`, `notes: null`) must not throw → Task 1 tests.
5. Dashboard links with filters (`/admin/skills?filter=orphan`) must open the matrix already filtered, including after a refresh → Task 3 test on `parseMatrixFilter`.

  - `saveResource(key, data, isNew)` additionally accepts `data.skillIds?: string[]` for `experiences`/`projects`: strips it before schema parsing, then applies `diffLinks` against that item's current `skill_links` rows only.
